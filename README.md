# Minecraft AIfriends（MA）

给 Minecraft 服务器装**真的在玩的** AI 玩家。

每个 AI 是一个独立的人：有自己的名字、年龄、老家、学校、性格、口味、脾气。
不是一套参数配出来的"人格模板"，是一个完整的、有来历的人。

**他们都不知道自己是程序。** 这不是设定，是前提——
所有设计都建立在"他确信自己是个活人"之上。

```
[23:53:16] 死了：XJJ was slain by Zombie
[23:53:20] [say] 草，被僵尸挠死了
```

那句话不是从台词库里抽的。库里没有这句话。是模型看着"我刚被僵尸打死"这个处境，自己写的。

> 目前跑着第一个实例（下面的 `XJJ` 是他的游戏 ID）。角色设定放在 `config.json` 的 `persona` 里，
> 可以换人、可以同时跑多个。**代码里不写死任何具体角色。**

---

## 为什么做这个

现有的 Minecraft AI 大致两条路：

**一条是 Voyager 那样的**——很能干，会自己写代码解锁成就，但你跟它说话像在跟 CLI 交互。它是个高效的工具。

**一条是聊天 NPC**——能陪你唠嗑，但你不能指望它真的去挖矿。它是个会说话的雕像。

两个都不是"玩家"。玩家是**又能干又像人**：会为了三块铁下矿，也会因为挖了半天没东西而骂娘；会记得你上周帮他打过僵尸，也会忘了你昨天说过什么。

MA 想做的是第三种。

---

## 现在他真能干什么

不是"设计上支持"，是**跑出来过的**：

| 事情 | 实测 |
|---|---|
| 砍一棵树 | 106 秒，拿到 5 块原木 |
| 做把木镐 | 3 秒（有材料时） |
| 做把石镐 | 19–35 秒 |
| 从 y=18 的地下爬回地面 | 48.7 秒，真寻路，不用传送 |
| 离家 95 格走回去 | 48.7 秒，误差 2.9 格 |
| 找点吃的 | 119 秒，打猎或摘果子 |
| 放箱子存东西 | 2–3 秒 |
| 挖 3 块石头 | `mine()` 本身 37.8 秒（扫描 0.2 / 挖掘 8.0 / 捡取 18.1）；端到端含造镐最好 252 秒 |

端到端 8 个典型任务跑下来，**成功率 25% → 67%**。剩下 33% 卡在哪，`docs/KNOWN-BOTTLENECK.md` 里一条条写着。

## 他怎么像个人

这一节是整个项目最难的部分，也是最容易做砸的。

### 会吐槽，但不是个喷子

```
挖半天啥也没有  → 这地方真没劲 / 白折腾
被怪弄死        → 骂一句，越短越好
合成失败        → 骂合成，或者说材料又不够
自己干成了      → 一句短的认可，不庆祝
```

**十句话里带情绪的不超过三句。** 剩下七句平铺直叙。

连着两句都在骂，一眼假。同一件倒霉事第二次提，要换个说法。

### 被骂有反应梯度

这一点第一版做砸了。玩家上来就骂，他回"又咋了果哥，上来就骂人"，再骂一句，他回"有事说事，骂来骂去没意思"。

**这是客服，不是人。**

真人被无缘无故骂是这样的：

```
第一次 → 懵。"？" "我干啥了"
继续骂 → 火。"你有病？" "招你惹你了"
还骂   → 骂回去。短、狠、不解释
```

**"有事说事""骂来骂去没意思"这类劝人向善的话，打游戏的真人说不出来。**

### 不问名字

第一次见你，他就用你头顶那个游戏 ID 喊你。

不会问"怎么称呼"——真人不会每次见到新面孔都问一遍。只有你主动说"叫我老王"，他才改口。

**问名字是最典型的机器人开场白。**

### 会忘事

| 记什么 | 多久 |
|---|---|
| 普通事件 | 6 小时半衰期 |
| 恩怨 | 40 小时 |
| 承诺、技能 | 不忘 |
| 刻骨铭心的（情感 ≥0.7） | 永不遗忘 |

**但"重复念叨"不会让他记住。** 一句"还差点石头"说八遍，也不会变成刻骨铭心——这条是踩过坑才修好的。

### 有自己的事要做

没人管他的时候，他不会站着等你发话。

他想弄把好点的镐、想盖个屋、想去前面那座山看看。这些念头从他自己身上长出来，不是从任务列表里读出来的。

**品味也是自己长的。** 不预设他喜欢高处还是讨厌地下——玩久了才知道。

### 心情影响他理不理你

会累、会烦、会兴头上。

你喊他做事，他愿不愿意看当时心情。心情差的时候求他，可能直接被顶回来。

**但拒绝不是终点**：好好说、给点好处、硬来，效果不一样。磨久了会松口。威胁能让他听话，但他会记着。

### 不作弊

不会 `/give`、不会 `/tp`、不会 `/gamemode`。

跟普通玩家一样靠两条腿走路、靠镐子挖矿。

## 他看不见方块，他看见地形

大部分 Minecraft bot 拿到的世界是这样：

```json
{ "stone": 1234, "dirt": 800, "oak_log": 3 }
```

一堆数字。知道有多少石头，不知道石头在哪、头顶有没有、走不走得过去。

MA 给他的是这个：

```
【东西方向剖面】
x-2: ██████████
x-1: ██████████
x+ 0: █████··███  ← 你在这
x+ 1: █████··███
x+ 2: ██████████

【俯视图】
z+ 0: ████····█████  ← 你
z+ 1: ████C···█████

【四个方向】东能走（要挖2格），西走不通（脚下悬空），南能走，北能走
```

`█`实心 `·`空 `~`水 `L`岩浆 `T`原木 `t`树叶 `O`矿石 `C`容器

**一眼能看出：前面通不通、头顶压着什么、从哪边走代价最小。**

这一改动的效果比想象中大——之前他经常"朝着一个走不到的地方挖"，因为他根本不知道那地方走不到。

## 他怎么学新本事

遇到不会的事，他不是报错退出，是**写一段代码去试**。

```
目标：做把石镐
  ↓
模型读地形图 + 背包 + 技能库，写出一段 JS
  ↓
在沙箱里跑（没有 require、没有网络、没有文件系统）
  ↓
失败 → 错误信息喂回去，重写（最多 4 次）
  ↓
成功 → 这段代码存进技能库
```

下次遇到同类事，**直接复用上次跑通的代码**，不再问模型。

实测任务复用率 **93.7%**（359/383）。

⚠️ 但这里有个坑：最热的技能复用 **19 次、0 次成功**。
因为"成功"判的是"代码没抛异常"，不是"事情真的做成了"。
这个问题正在修（见 `docs/UNHUMAN-SCAN.md` #8）。

**这意味着他的能力上限不是代码写死的**，是模型给多少。

## 架构

```
L5  意愿层    他自己想干嘛
    ├ 长期目标   跨天的目标，拆成阶段，会放弃会冷却
    ├ 品味       自己长出来的偏好，不预设
    └ 心情       累/烦/兴头上，影响他愿不愿意做事

L4  人格层    他是谁
    ├ 记忆       会忘事，有半衰期
    ├ 说服       求/给好处/威胁，效果不同
    ├ 价值观     什么该做什么不该做
    ├ 秘密       不会主动说，但能被套出来
    └ 家         有基地，离太远会想回去

L3  技能库    做成的程序存下来，按处境检索复用

L2  程序层    模型写 JS → 沙箱执行 → 失败回喂重写

L1  原子动作  走/挖/放/合成/冶炼/吃/装备/战斗/开箱…

L0  反射层    每 800ms：自救/脱困/逃跑/还手/捡东西/天黑躲藏
    ├ 感知     地形图、事件队列、自我状态（血/饿/工具耐久）
    └ 记忆     刚才发生了什么

L-1 身体      mineflayer，掉线重连，死了自动复活
```

### 为什么分这么多层

**反射层必须比模型快。** 血掉到 6 的时候不能等 LLM 想 3 秒再决定跑不跑——每 800ms 的本地检查救命。

**程序层必须比反射层聪明。** "做把石镐"这种需要规划依赖链的事，写死代码永远做不全。

**意愿层必须比程序层自由。** 没人告诉他要干什么的时候，得有个东西替他拿主意。

三层缺一层，他要么是个呆子，要么是个工具。

## 快速开始

```bash
git clone https://github.com/lg5874/Minecraft-AIfriends.git
cd Minecraft-AIfriends
npm install

cp config.example.json config.json
# 填 llm.apiKey / bot.host / bot.port

npm start
```

需要：
- Node.js ≥ 18
- 一台 Minecraft Java 版服务器（Paper 1.21.x 实测可用）
- 一个 OpenAI 兼容的 LLM 接口

### 支持多个模型自动切换

主模型挂了自动切备用，恢复后自动切回：

```json
"llm": {
  "providers": [
    { "name": "主",  "baseUrl": "https://api.example.com/v1", "apiKey": "sk-xxx", "model": "deepseek-v4.1-flash" },
    { "name": "备1", "baseUrl": "https://api.backup.com/v1", "apiKey": "sk-yyy", "model": "deepseek-v4.1-flash" }
  ]
}
```

切回策略是**指数退避探测**：主模型失败后 30 秒探一次，没通就 1min → 2min → 5min → 10min → 30min。
探测请求只有 `max_tokens=1`，成本几乎为零。

对比固定 30 秒轮询：主模型挂 2 小时，轮询要打 240 次，退避只打约 10 次。

## 部署到服务器

不想让他跑在你电脑上？`mcplugin/` 里有个 Paper 插件，能让他常驻服务器。

```bash
node scripts/package.js                    # 打包（268 KB）
cd /root/workspace/mcplugin && ./build.sh  # 编译插件（52 KB）
```

> `mcplugin/` 目前不在这个仓库里（在 `../mcplugin`）。要合并进来见 BACKLOG。

传到服务器的 `plugins/`，面板点启动，填好 key 就能跑。

**磁盘占用约 340 MB**（主要是 `minecraft-data` 的方块数据），文档里写了怎么再瘦身。

详细步骤见 [docs/DEPLOY.md](docs/DEPLOY.md)。

## 已知问题

**能力**
- 盖房子是逐块摆的，歪歪扭扭
- 天黑躲藏会挖坑，但封顶不稳
- 挖矿拾取不稳定（服务器 TPS 低时会丢掉落物，不是客户端能修的）

**行为**
- 有长期目标后仍偏向往下挖（已加"地下待久了想上来"，但阈值是估的）
- 回家成功后容易立刻又钻回地下

**工程**
- 长时间跑（几天）没测过稳定性
- 部署到服务器还没实际跑过（产物和文档齐了）

**环境依赖**
- 基岩版客户端必须 ≤ 26.52.3（Geyser b1279 限制）

## 一个提醒

这个项目里最难的从来不是"让他会做什么"，是**"让他做得像个人"**。

写个能砍树的 bot 需要一下午。
让他砍完树之后骂一句"这树真难砍"，然后接着干下一件事——这个花了几个月，现在也还不完美。

判断标准只有一条：

> **如果没人告诉你他是 AI，你多久能发现？**
