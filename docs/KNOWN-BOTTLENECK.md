## 已解决的瓶颈（存档，避免重踩）

### 1. `pickupNearby` 只做水平寻路 ✅
**现象**：方块真挖掉了、掉落物真生成了，就是捡不到。实测 0/5。
**根因**：bot 站 y=72，泥土在 y=70，垂直差 2 格。
原版拾取半径是玩家 AABB 外扩 1 格，垂直差 2 格永远碰不到。
而 `pickupNearby` 全程只做水平寻路（GoalBlock 走不过去就跳过）。
**修法**：加垂直分支——物品在脚下 >1.4 格时，GoalBlock 直接下到那层；
站不了就蹲着走过去靠重力落。
**实测**：修前 0/5 → 修后 5/5。
**影响**：这是整条链的总闸。泥土能捡 → 垫脚料有了 → 塔升生效 → 砍树也通了。

### 2. `gotoVertical` 随机漂移 ✅
**现象**：日志里 bot 越走越远，从树旁 6 格漂到 30 格外。
**根因**：`gotoVertical` 里每轮 `Math.random() * 6` 随机偏移 ±3 格。
挖一格要 40 轮 × 每轮随机走 = 甩出去几十格。
**修法**：朝目标方向固定小步移动。

### 3. `mine()` 扫描 88,725 次 blockAt ✅
**现象**：挖石头 301 秒超时。
**根因**：`for dx in -32..32 × dy in -10..10 × dz in -32..32` = 88,725 次 `blockAt`。
**修法**：换成 `findBlocks` + y 过滤。
**实测**：187ms → 8ms，23.4 倍。有镐时挖石头 30-45 秒（目标 <60s）。

### 4. 塔升震荡：空手也挖石头 ✅
**现象**：`tryPillar` 里 y 在 54↔55 反复几十次，净上升 0。
**根因**：`tryPillar` 的"自己造料"那段**空手时也在挖头顶石头**：
- 挖掉 granite → 0 掉落（空手挖石头不掉料）
- 地形被破坏一块，料还是 0
- 下一轮又挖一块 → 再下一轮……
在"挖石头 → 没料 → 放弃 → 再挖石头"之间打转。
**修法**：`tryPillar` 和 `stockFiller` 用同一套判断——
没镐时只挖 `dirt/grass_block/gravel/sand/clay`，绝不碰 `stone/granite/andesite`。
**实测**：修后零震荡。

### 5. `ensurePickaxe` → `chopTree` → `getToSurface` → `ensurePickaxe` 死锁 ✅
**修法**：`_surfaceRunning` 标志位，反向调用回来时跳过做镐。
**但**：实测做镐成功 0 次（地下没树，绕一圈回原点，纯浪费 100 秒）。
所以主流程不再主动做镐，只留防死锁标志。

### 6. 砍树走不到 ✅
**现象**：`[chop] 走不到这棵（差 6.0 格），换下一棵` 连续刷。
**根因**：不是"走不过去"，是"垂直爬不上去"。
候选格距树干 1.73~2.83（远在 4.2 内），但人在 y=65~66，候选在 y=70~71，差 4~5 格。
背包空时 `allow1by1towers` 没有垫脚方块 = 废的。
**修法**：
1. `goNearTree` 垂直段改"挖台阶上升"（`digStairUp`，不依赖垫脚方块）
2. `digAt` 加 `walkToBlock` 选项（挖树干时禁止自己 goto 漂移）
3. 修 `gotoVertical` 随机漂移
**实测**：砍树从 113s 失败 → 27s 成功（原木 1→2）。

## 当前死结（2026-11-13 10:30）

### `craftSmart` 不会自动做木棍

**现象**：`木板 16 / 木棍 0` 时，`craftSmart('wooden_pickaxe')` 失败。
木镐 = 3 木板 + 2 木棍，木棍 = 1 木板 → 4 木棍。有 16 张木板绝对够。

**实测（ensurePickaxe 160 秒）**：
```
[chop] 砍下 4 块原木 @86,76,73
[planks] oak_log -> oak_planks x16
[tool] 木板 16 / 木棍 0 / 原木 0
[tool] 做木镐失败: 合成 wooden_pickaxe 后背包没变化（0/1）
[tool] 再补一轮原木
[tool] 补料后做成了木镐        ← 补一轮就成
```

**影响**：挡住 3 个任务（挖石头 / 做木镐 / 做石镐）。
现在要 160 秒 + 砍两轮树；修好后应该 80 秒一轮。

**疑似根因**：`craftSmart` 递归调用时，`recomputeNeeds` / `pick` / `times0`
这几个变量的作用域可能串了（木镐的配方上下文和木棍的配方上下文混在一起）。

### 已修的前置条件

1. `ensurePickaxe` 加了"先攒垫脚料"步骤（空手能挖 dirt/grass_block/gravel/sand/clay）
2. `digAt` 的挖脚下检查误杀（下面没方块时 continue，不再 return false）
   —— 之前砍树时报"这棵砍不动（差 1.1 格）"，1.1 格明明够得着
3. `chopTree` 的扫描半径逐级放大（48 → 64 → 80），实测"半径放大到 64 格后找到 2 棵"

## craftSmart 补料顺序问题（2026-11-13 11:05）

### 现象
```
✅ 砍树    63s  原木 0 -> 7
❌ 做木镐   1s  补料 1 遍后仍缺：oak_planks 要 3 有 1
```

背包有 7 个原木，却做不出 3 张木板。

### 推演
```
初始: 原木 7, 木板 0, 木棍 0
目标: wooden_pickaxe = 3 木板 + 2 木棍

第1遍:
  needs = { oak_planks: 3, stick: 2 }
  补 oak_planks: 1 原木 -> 4 木板    → 木板 4 ✅
  补 stick:      2 木板 -> 4 木棍    → 木板 2, 木棍 4  ⚠️ 消耗 2 张
第1遍结束: 木板 2 < 3 ❌
```

### 根因
`recomputeNeeds()` 只在每遍开头算一次。
同一遍内部，补 stick 会消耗 planks，但 needs 里的 planks 需求没跟着更新。

### 修法（三选一）
- **A** 补料顺序改成先补会被消耗的（stick 先于 planks）
- **B** 每补一项就重算 needs（改动最小，推荐）
- **C** 按完整依赖树一次性备齐

### 另一个问题：找食物退步
```
❌ 找食物  90s  findFood 返回 "拿到 kelp x2"
```
海带不是食物（查过 mcData：`kelp` 不能吃，`dried_kelp` 才行）。
判据要改：拿到 kelp 但没烤，不算成功。

## 「每次见他都在地下」的两个机制层根因（2026-11-13 16:50 定位）

### 实测数据（12 分钟，36 个采样点）

```
y 范围：18 ~ 41（家 y=64）
在地下（y<50）：100%     ← 36/36 采样点
水平距家：81~83 格
垂直距家：46 格
触发 isFarFromHome(96)：0/36 次
```

**100% 在地下，不是巧合。**

### BUG-A：`isFarFromHome()` 只看水平距离

```js
isFarFromHome (d = 96) {
  return this.hDistanceFromHome() > d    // ← 只算水平
}
```

实测那一幕：水平 82 格、**垂直 46 格**、三维 94 格。
旧判定 `82 < 96` → "不远" → **永远不回家**。

### BUG-B：只有死后复活才触发回家

`tryGoHomeAfterRespawn()` 只在 `afterRespawn()` 末尾调一次。
活着干活时**没有任何"该回家了"的判断**。

所以他在地下越挖越深，家在身后 90 格、46 格高，没有任何理由往回走。

### 修法（已实现）

1. **`walkCostHome()` = 水平 + 垂直×3**
   垂直一格算 3 格：水平 80 格走 40 秒；垂直 40 格要挖楼梯/垫柱子，1-3 分钟还常卡住。

2. **`shouldHeadHome(st)`** —— 代价超过收益才回，不是"离家就回"
   | 触发 | urgency |
   |---|---|
   | 回家代价 > 140 | 0.8 |
   | 地下深度 > 25 格 | 0.6 |
   | 背包空格 ≤ 2 | 0.7 |
   | 镐子没了 | 0.75 |
   | 饱食度 ≤ 6 | 0.65 |
   | 血 ≤ 8 | 0.5 |
   `urgency < 0.5` 不打断手头的活。地表同层挖 60 格不会被打断。

3. **主循环每轮问一次 `tryHeadHome()`**（`main.js` tick 第 6.5 步）

4. **`homeResourceHint()`** —— 把"家附近 40 格有橡木、石头"写进提示词

### 实测效果

```
[16:46:39] 进来了：XJJ @ (58.5, 18, -9.5)
[16:46:39] [home] 该回家了：离家太远（走回去约 9 分钟），在 46 格深的地方
[16:47:27] [home] 到家了：48.7s，还差 2.9 格
```

**从 y=18 的地下深处，48.7 秒真寻路爬回 y=64 的家。**

### 还没解决的（第 3 个根因）

回家成功后他立刻又往下挖了：
```
16:47:39 到家
16:48:39 已经到 y=60
16:50:09 到 y=55
```

**"回家"只解决了"回到地面"，没解决"为什么总想往下钻"。**
那是 `goals.js` 的长期目标（"一直往下挖，挖到钻石为止"）驱动的。
已派 goals-owner 修（加了 `getup` 目标和 `surface` 阶段）。
