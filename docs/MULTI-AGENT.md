# 多 AI 共存验证（MULTI-AGENT）

> 项目叫 **Minecraft AIfriends**，README 第一句承诺"每个 AI 是一个独立的人"。
> 这份文档回答一个从没被验证过的问题：**两个 AI 在同一个服务器，会不会互相干扰、串味、打架。**

实测时间：2026-11-13 22:48–22:54（6 分钟）
实测账号：`XJJ_MAf3d32x` / `XJJ_MBf3d32x`（独立数据目录、同一服务器）
探针：`scripts/probe-multi.js`（`node scripts/probe-multi.js --minutes 6`）
原始结果：`data/probe-multi/f3d32x/result.json`

**只做分析和验证，没有改 `src/` 下任何文件。** 修改建议见第三节，由 Lead 派单。

## 0. 结论先说

| # | 问题 | 结论 | 严重度 |
|---|---|---|---|
| 1 | 互相认不出来 | **认人没问题，识"同类"有问题**：档案里互相记得对方，但没有任何"它也是 AI"的判定，防对刷机制全程没触发（`[chain]` 0 次） | P1 |
| 2 | 资源冲突 | **没有协调机制**。目标层互不共享，两人活动盒实测重叠（x 间距 0 格），6 分钟内没爆冲突只是运气 | P2 |
| 3 | 对话错乱 | **会发生，但不是"串台"**：各说各的、没有串台；问题是**互相当真人**（无轮次上限）+ **推理句漏到公屏**（"我第一次见这些人，不熟。）"）+ **一秒 11 条爆发** | P1 |
| 4 | 记忆混淆 | **没有发生**：两个数据目录独立，目标/背包/技能不串。发生的是**"把对方说的话记成事件"**（设计内）和**人物档案被测试号污染**（P0，见下） | P0（污染）/ 无（混淆） |

## 1. 静态分析

### 1.1 "我是谁"——自我排除是齐的

| 位置 | 做什么 |
|---|---|
| `main.js:138` / `:159` / `:164` | playerJoined / left 里跳过 `username === bot.username` |
| `main.js:172` | `chat_me`：只有消息里出现自己的名字才当"有人叫我" |
| `src/talk.js:280` | 收到自己的话直接 return |
| `src/perceive.js:445` | `describePeople` 列表里排除自己 |
| `src/audience.js:204` | 被注视扫描排除自己 |
| `src/events.js:578` | 事件队列排除自己的名字 |
| `src/spontaneous.js:703` | 打招呼排除自己 |

**结论**：不会把自己当成别人。这一层没问题。

### 1.2 "对方是不是同类"——只有两条名字正则

全项目没有"另一个 AI"这个概念，只有两处"名字像 bot 就防着点"：

```js
// src/talk.js:813
if (/^(bot|ai|npc|_bot|bot_|XJJ\d+|Test\d*)/i.test(name)) return true   // 对话层
if (this.ctx.botNames && this.ctx.botNames.includes(name)) return true

// src/spontaneous.js:510
return /^(bot|ai|npc)[_-]?\d*$/i.test(n)                                 // 打招呼层
```

问题：

1. `XJJ\d+` **只认 XJJ 后面紧跟数字**（XJJ1、XJJ2）。真实的同伴账号一旦叫 `XJJ_MA…`（下划线）或 `XJJMULTI…`（4 位以上字母数字）就**不匹配** → 对方被当成真人 → 防对刷整段失效。
2. `behavior.botNames` 是**唯一**能让两个 AI 互相认出来的配置（`main.js:414` 传给 Talk；`spontaneous` 通过 `this._talk.ctx.botNames` 取）。实测没配，所以全程当真人。
3. 防对刷本身写好了却用不上：`talk.js:284-300` 的 `botChain`（2 分钟内同一人聊满 3 轮就断）只在 `isBotLike` 为真时执行。

**这决定了两个产品方向**：
- 要"朋友感"（像真人一样聊）→ 不配 `botNames`，但要**另加轮次/速率限制**兜底；
- 要"不刷屏"→ 配 `botNames`，代价是它们对彼此说得更少（50% 概率回、3 轮断），也不再互相打招呼。

### 1.3 数据隔离——这是最容易翻车的地方

```js
// main.js:44
const DATA = process.env.AIFRIEND_DATA
  ? path.resolve(ROOT, process.env.AIFRIEND_DATA)
  : path.join(ROOT, 'data', 'runtime')     // ← 不设环境变量 = 两个实例写同一批文件
```

- ~~**没有实例锁**~~ → **已修（2026-11-13）**：新增 `src/instance.js`，`main()` 启动时在 `DATA/.instance.lock` 写 pid + 进程启动时间；同目录已有活实例就拒绝启动。（`src/actionlock.js` 的 `ActionLock` 是另一回事：它管一个进程内部的几条动作线，跨实例不管。）
- ~~`memory/index.js:153` 的 `save()` 是整文件覆盖~~ → **已修**：改成 tmp + fsync + rename，进程被杀/断电都不会留半截 JSON。
- 实测（单机两实例、同一目录）：

```js
const a = new Memory(dir); const b = new Memory(dir)
a.add({text:'第一次见到 XJJ_MB1', ...})   // A 写盘
b.add({text:'第一次见到 XJJ_MA1', ...})   // B 写盘（B 内存里没有 A 那条）
读盘结果: [ '第一次见到 XJJ_MA1' ]        // A 那条被静默吞掉
```

**后果**：两个人用默认目录起，谁的记忆最后写谁说了算，另一方"失忆"，而且没有任何报错。

### 1.4 资源协调——完全没有

- `src/goals.js:602 candidates()` 只看自己的背包/坐标/品味，**不看附近有没有别的 AI**（grep 不到 `players`）。
- 寻路（mineflayer-pathfinder）不把玩家当障碍；两个 AI 会互相挡路。
- 箱子/工作台没有占用标记（`home.js` 只认自己那份 `home.json`）。
- 唯一兜底是单机的 `src/actions.js:7698`：`throw new Error('方块没了（name）')` —— 对方先挖掉，这边抛错，上层当失败处理。

### 1.5 被注视——两个 AI 会互相触发

`src/audience.js:190-211` 把**所有非自己玩家**当观众，除非 `ignore()` 返回真。`main.js:517` 把 `ignore` 接的是 `spont._looksLikeBot` —— 也就是 1.2 里那条只认 `XJJ数字` 的正则。

所以两个"人类名字"的 AI 站在一起会**互相被视为注视者**，各自改变挖方块节奏、抬头频率。两个人自己看自己，会形成互相影响的回路。

### 1.6 测试号过滤——下划线命名全部漏网

```js
// src/memory/writer.js:176
const TEST_ACCOUNT_RE = /^XJJ[A-Z0-9]{4,}$/      // talk.js:845 是同一套
```

实测判定：

| 账号 | 进人物档案？ |
|---|---|
| `XJJ_MAf3d32x` / `XJJ_MBf3d32x` | ✅ 进（下划线不匹配） |
| `XJJ_S5wi3` / `XJJ_GD525`（同服其他 agent 的探针） | ✅ 进 |
| `XJJMULTI2` / `XJJHOME6` | ❌ 不进（正确过滤） |

**这条是 P0**：现在所有"探针/小号"都习惯用 `XJJ_XXX` 下划线命名，于是它们会以 0.6 importance 进入"认识的人"，长期占据 `peopleDigest` 名额 —— 正是 UNHUMAN-SCAN #13 想修的那个病，换了个命名就复发。

## 2. 实测（6 分钟，同一服务器）

同服还有别的 agent 的 bot（`XJJ`、`XJJ_GC774`、`XJJ_S5wi3`、`XJJ_S6lpx`、`XJJ_GD525`），所以这其实是一次**多 AI 环境的真实采样**，不只是一对一。

### 2.1 互认：记得对方，但当真人

```
A 的人物档案：XJJ、XJJ_MBf3d32x、XJJ_GC774、XJJ_S5wi3、XJJ_S6lpx、XJJ_GD525
B 的人物档案：XJJ_S5wi3、XJJ、XJJ_MAf3d32x、XJJ_GC774、XJJ_S6lpx、XJJ_GD525
```

- 两人都记得对方（`第一次见到 XJJ_MB…`），也会把对方说的话记成事件：
  - A 记：「我第一次见这些人，不熟。）」
  - A 记：「苦力怕就苦力怕呗 反正又不掉东西」
  - B 记：「掉岩浆里了呗」
- `[chain]`（防对刷）**0 条** —— 全程把对方当真人。

### 2.2 对话量：能聊，但没人踩刹车

| | A | B |
|---|---|---|
| `[say]` 发言 | 105 句 | 31 句 |
| `[chat]` 收到/处理 | 200 行 | 474 行 |
| 去重拦下（"这条已经回过了"） | 83 | 214 |
| "忙着/这会儿腾不出手" | 107 | 254 |
| `[chain]` 防对刷 | 0 | 0 |
| **单秒最多发言** | **11 条** | 5 条 |

爆发样本（22:52:45，A 一秒内 11 条）：

```
嗯 那就走呗 / 知道了 这就跟上来 / 没细看 / 土有用啊 垫脚填坑都行
不知道啊 没看见他 / 不知道啊 我也没看见 / 哦 来了 / 跟上了
```

内容没错，但**一秒 11 条公屏**在真人里不存在；这是"多人同时对话 + 回复队列一起放出来"。

### 2.3 内容错乱：推理句漏到公屏

实测原句（我们自己的 bot 说的，不是对方）：

```
A: 嗯，从刚才的对话看，XJJ刚上线，之前我        ← 半句推理，半句截断
B: 我第一次见这些人，不熟。）                   ← 旁白括号漏出来
B: ，掉岩浆里了                                  ← 开头缺主语
```

多 AI 环境下更容易出现：对话频繁 → 抢着回 → 模型把"思考"当"台词"输出。这是 `talk.js` 的生成/过滤问题，单机也有，但**多 AI 会把它放大**。

### 2.4 外部 bot 的提示词注入（真实发生）

两个 bot 都收到同一条公共聊天：

```
现在你该说一句话接上。对方说了「邪门」，
```

这是另一个 agent 的 bot 把自己的 **prompt 片段发进了公屏**。我们的处理：

- 进了 `talk.onChat` 的回复决策（被"这条已经回过了"拦下，没回）；
- 记忆准入挡住了：`memory.json` 里相关条目 **0 条**（准入把它当"不是记忆"丢了）。

**结论**：这次没造成污染，但**聊天层没有显式的"指令型文本"拦截**。多 AI 共服时，别人 bot 的泄漏就是你的输入。

### 2.5 资源与目标：没协调，这次没撞

| | A | B |
|---|---|---|
| 长期目标 | 攒够材料盖个小屋 | 挖一趟铁就上来 |
| 活动范围（`[hb]` 采样） | x 25..74, z -86..-2（10 次） | x 62..113, z 8..82（11 次） |
| 报错 | 0 | 0 |

两块活动区 **x 方向间距 0 格、z 方向 10 格** → 同一片 48×48 区域。这次目标不同（盖房 vs 挖铁）才没抢；目标相同就是同一片树/石头。

### 2.6 动作冲突：6 分钟没触发

没有 `Block is not diggable` / `方块没了` 报错。原因见 2.5：两人目标不同、活动时序错开。**不能据此认为没问题**——需要定向测试（两人同时挖同一块、同时开同一个箱子）。

## 3. 要改的地方（按优先级）

### P0-1 数据目录隔离 + 实例锁 —— ✅ 已修（2026-11-13）

- 改动：
  1. 新增 `src/instance.js`：`acquire(DATA, {username})` 独占创建 `DATA/.instance.lock`
     （`openSync(file,'wx')`，两个实例同时起也只有一个成功），内容是 `{pid, start, at, username}`。
     判活不只看 pid：还比对 `/proc/<pid>/stat` 的启动时间，**pid 被复用也能识别成 stale**。
     正常退出在 `process.on('exit')` 里删锁；`kill -9` 留下的锁由下一个实例判定 stale 后接管。
  2. `main.js` 启动段：拿不到锁就打印并 `exit(1)`；不设 `AIFRIEND_DATA` 时打两行警告。
  3. `src/memory/index.js` `save()`：tmp + fsync + rename（跟 goals/home/session 对齐）。
- 验收（实测）：
  ```
  # 同目录第二个实例
  [启动] 这个数据目录已经有一个实例在跑（pid 23625，起于 23:03）
         要么关掉它，要么用 AIFRIEND_DATA 换个目录        → exit 1

  # 正常停掉后 / kill -9 之后
  [启动] 数据目录 data/probe-lock/node（实例锁已拿到，pid 31384）   → 正常启动

  # 不设 AIFRIEND_DATA
  [启动] 没设 AIFRIEND_DATA，用默认目录 data/runtime
         跑多个 AI 时必须各自设一个，否则会互相覆盖记忆

  # kill -9 八个不同时间点打 memory 保存：memory.json 始终可解析，重新 load 正常
  ```
- 仍然成立的风险：**同一个目录被两个实例先后启动是安全的，但同时运行仍然禁止**（这是设计）。
  另外 `clock.json` 等小文件仍是直接写，不保证原子 —— 影响仅是"少记一次在线时长"。

### P0-2 测试号过滤覆盖下划线命名

- 现状：`src/memory/writer.js:176` `TEST_ACCOUNT_RE = /^XJJ[A-Z0-9]{4,}$/`；`talk.js:845` 同款。
- 实测：`XJJ_MAf3d32x`、`XJJ_S5wi3`、`XJJ_GD525` 全部进了人物档案。
- 建议：判据改成**显式清单优先 + 宽松正则兜底**：
  - 配置 `behavior.testAccounts: [...]`（探针/小号写这里）；
  - 正则补下划线：`/^XJJ[_-][A-Z0-9_]{3,}$/`；
  - 保留主账号白名单（现在已有，别再动）。

### P1-1 让 AI 之间至少有限流（是否"认同类"是产品选择）

- 现状：两个正则都不认 `XJJ_MA…`；`botChain` 从不生效。
- 建议二选一（**需要 Lead 定方向**）：
  - **A. 朋友感优先**：不配 `botNames`，但 `talk` 加**发言速率限制**（例如 3 秒最多 1 条，被点名时可放宽到 1 秒 1 条）+ 单次上线对同一人最多 N 条。这条不管是不是 AI 都该有。
  - **B. 防刷屏优先**：把同伴写进 `behavior.botNames`，让现有的 `botChain`（3 轮断、50% 回）生效；代价是它们互相不打招呼、回得更少。
- 建议先做 A（对真人也有用），B 作为更严格的可选。

### P1-2 说话内容过滤（推理句/截断/旁白）

- 现状：实测出现 `嗯，从刚才的对话看…`、`我第一次见这些人，不熟。）`、`，掉岩浆里了`。
- 建议在 `talk.say()` 出口加三道闸（属于 talk 的地盘）：
  1. 括号/引号未闭合 → 不回；
  2. 出现"从刚才的对话看/我需要/根据以上/作为 AI"这类旁白词 → 不回；
  3. 以逗号、句号开头且主体缺失 → 不回。

### P1-3 聊天层的指令型文本拦截

- 现状：外部 bot 的 prompt 片段进了 `talk.onChat` 的决策链（本次记忆层挡住了，但那是最后一道）。
- 建议：`talk.onChat` 开头加一道识别（`你该/请回答/系统提示/你现在是/别忘了规则` 等）→ 只记日志不入队、不进记忆。

### P2-1 资源冲突：先做"看得见"，再做"调度"

- 现状：`goals.candidates()` 不看邻居（`src/goals.js:602`）。
- 建议（低成本）：`perceive` 已经能看到附近玩家在干嘛（`guessPlayerDoing`）。把这个信息喂进 `candidates()` 的提示词/评分：**附近有别的 AI 正在做同一类活 → 该方向降权 10~20 分**。
- 不建议做集中锁：两三个 bot 用 gossip 会比锁简单，且不会互相卡死。

### P2-2 被注视不要互相触发

- 现状：`audience.ignore` 接的是 `spont._looksLikeBot`（`main.js:517`），认不出同伴。
- 建议：同伴名单（`botNames` 或新增 `peerBots`）同时喂给 `audience.ignore`，否则两个 AI 会互相"盯着看"→ 互相改节奏。

### P2-3 对话爆发限速

- 现状：单秒 11 条（2.2）。
- 建议：`say()` 层做全局节流（见 P1-1 A），并给"回复队列"设上限（排队超过 N 条就丢最旧的）。

## 5. 定向冲突（补充实测）

> 之前的"动作冲突 0 条报错"只是**没观测到**。这一节把两个 bot 的动作卡在同一毫秒，测清楚会发生什么。

### 5.0 方法

```bash
node scripts/probe-multi.js --conflicts
```

- 用**两个裸 mineflayer 连接**（不是两个 main.js）：AI 的挖/开箱子最后都落到 `bot.dig` / `bot.openBlock`，冲突就发生在这一层；裸连接能把两个动作卡在同一毫秒，AI 循环做不到这种精度。
- 代价：测不到 `actions.js` 自己的兜底文案，这一节最后用代码定位把那部分对上。
- 服务器对同 IP 有连接限流（`Connection throttled`），探针内置了 20 秒重试；实测需要重试 1~2 次。
- 账号 `XJJ_CA…` / `XJJ_CB…`（带时间戳），两个连接各自独立，不写任何数据目录。

| 同开一个容器 | `crafting_table @77,69,7` | 两个都打开成功（各自一个 `minecraft:crafting` 窗口，A 990ms / B 101ms） | 无 |

| 一个睡觉另一个挖 | — | 32 格内没有床 | — |

原始数据：`data/probe-multi/conflicts-f4iqco/result.json`（含每次调用的耗时与错误）。

### 5.2 结论：最严重的问题不是"报错"，是"两人都以为自己挖到了"

```
[同挖一格] 两人都报成功｜方块最终：air｜到手：A+1 B+0
   A: 成功 907ms
   B: 成功 969ms
```

`mineflayer` 的 `bot.dig()` 在**方块变成空气**时就 resolve，不看是谁挖掉的。所以：

- 后挖的那个会"成功"返回，但掉落到手 0 个；
- 在 AI 层，这就是一次**假成功**（UNHUMAN-SCAN #8 的多人版）：他说"挖到了"，背包没变；
- 两个人都会记一笔"我挖到了"，实际只有一个人拿到东西。

项目里已经有这条自省（`src/actions.js:1612`「digAt 的返回值不可信，它 bot.dig() 一返回就 return true」、`:1289` 的实测注释、`:7698` 的 `方块没了`），但**判据仍然依赖单次 dig 返回**。多 AI 同服会把这条命中的概率抬高。

**建议（P1）**：把"挖到了"的判据统一成**背包净增 / 方块确实消失 / 掉落物被自己捡到**三者之一，而不是 `dig()` resolve。项目里 `verifyTaskEffect()` 已经在做硬判据，让 `dig` 这条路也走它。

### 5.3 容器/工作台：服务端没有锁，也不会报错

两个连接同时 `openBlock` 同一个工作台，都成功、各自一个窗口。也就是说：

- **不会报错，也不会卡死**；
- 但"同时往同一个箱子放/取"没有互斥，最终物品归属看谁先提交 —— 这是业务层要约定的（共同基地的箱子建议一人一个）；
- `actions.js:4514` 的注释已经写明"openBlock 不做距离校验"，用之前必须自己判距离（探针里就是这么做的：先 `pathfinder` 走到 3 格内，否则会把"够不到"误判成"冲突"）。

### 5.4 没测到的（环境限制）

- **箱子**：附近 24 格只有工作台；要测真箱子得先造一个（4 木板的成本可接受，但这轮没做）。
- **床**：32 格内没有床；造床要 3 羊毛 + 3 木板，成本高且涉怪物掉落，本轮跳过。
- **同放一格**：两人凑不齐可放置方块 —— 注意这本身也是冲突的副产品：**同挖一格时只有一个人捡到掉落**，另一个人"挖了但什么都没有"。

### 5.5 一句话

> **不会卡死，但会"双份假成功"。** 多人环境把 UNHUMAN-SCAN #8 从"偶发"变成"每次抢同一块都发生"。

## 6. 局限（没验到的）

1. 只跑了 6 分钟、两个实例；没做"两人同时挖同一块方块""同时开箱子"的定向冲突测试。
2. 同服有别的 agent 的 bot，对话数据里混入了第三方（这既是噪声，也是真实环境）。
3. 没验证三个以上实例；没验证 `peerBots` 配置后的实际效果（还没实现）。
4. 没测"两个 AI 在不同数据目录但同一个家坐标"的情况（`home.json` 各自独立，箱子归属会重叠）。
5. 模型端点当晚有过 403/503，个别回合的回话缺失不是共存问题。
