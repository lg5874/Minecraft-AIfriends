## 一个自我纠正：记忆是通的，我差点误判

**错误的查法**：
```bash
grep "mem.entries" src/persona.js src/talk.js main.js
# 零结果 -> 差点下结论"记忆只写不读，是第六个没连上"
```

**实际的读取路径**（`src/memory/index.js:661` + `src/talk.js:751`）：
```js
const recalled = this.mem.remember(situation, { people, limit: 5 })
const msgs = [{ role: 'system', content: persona.systemPrompt(this.mem, stateLine, recalled, ...) }]
```

**记忆是「按当下情景检索」的** —— `remember(query)` 拿情景做查询，取最相关的 5 条塞进提示词。
**不是全量塞**，这是对的设计（不然提示词会爆）。

**所以：`entries` 不被直接 grep 到，不代表没被用。它走的是 `remember()` 这个入口。**

**这是今晚第五次「用错口径看数据」**（前四次：`uses≠ok+fail`、行号分母、`bot_count` 没标、趟数被重启污染）。

`agent-team-lead` skill 里已经有「grep 不到 ≠ 不存在」，**但我还是犯了 —— 因为检索词不对（找 `entries` 而不是 `remember`）**。

**加一条：不确定一个字段有没有被用时，先看那个模块有没有提供"读取接口"（`remember` / `recall` / `get`），再 grep 字段名。**

## 「从来不接别人的话茬」查清了：明天不会显现

**代码位置**：`main.js:1706`

```js
const chats = evs.filter(e => e.type === 'chat_me')     // ← 只处理"叫我"
if (chats.length && this.talk && !this.busy) { ... reply() }
```

**所以：**
- 有人叫他名字 / 问他话（`chat_me`）→ **会应** ✅
- 别人随便聊天（`chat_any`）→ **不接**

**盲执行人说「从来不接别人的话茬」，是因为它看的是多人服务器日志 —— 那 30 分钟里别人说了十几句，全是普通聊天，一句都没叫他。**

### 明天的真实场景不一样

用户一个人玩，说的话大概率是：
- 「XJJ 过来」→ `chat_me`（含名字）
- 「你在干啥」→ `chat_me`（问句）
- 「这地方真难找」→ `chat_any`（可能不接）

**所以前两种会应，第三种不会。** 这个比例是合理的 —— **真人也不会对每句自言自语都接**。

**结论：这条不是 bug，是设计。明天不需要改。**

**但如果明天用户抱怨"跟他说话他不太理"，那就该把 `chat_any` 也接上**（给个低概率，比如 30%）。

## 第七个「没连上」——这次的受害者是我自己

**我写的那条 travel 守卫，一次都没真正执行过。**

```js
// 我写的
if (this.goals && this.goals.stageProgress) {
  const pr = this.goals.stageProgress()   // ← TypeError
```

**`stageProgress` 是 `goals` 模块导出的函数**（`module.exports.stageProgress`），
**不是 `Goals` 的实例方法**。所以 `this.goals.stageProgress()` 抛错，
而外面包着 `try/catch` —— **静默失效，和今晚那五个 bug 一模一样。**

**修法**：改成用 `goals.status().progress`（那就是当前阶段的 ratio）。

**教训**：**加 `try/catch` 之前，先确认里头的调用真的能跑通。**
我这晚上一直在说「不是算错了，是没连上」，结果自己写了个没连上的守卫，
还因为加了 `try/catch` 而以为它是安全的。

**`catch` 里只写 `() => {}` 的，全部要改成 `log` + 分类** —— 这条我写进 skill 了。
