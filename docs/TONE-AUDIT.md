### 1.3 长度分布（证明"过于整齐"不是问题）

| 区间 | 条数 |

| 1–5 字 | 4 |
| 6–10 字 | 18 |
| 11–15 字 | 19 |
| 16–20 字 | 5 |

## 二、提示词哪里写得不够

逐条对着 `src/persona.js` 改前的版本（225 行）说。

### 问题 1：反例句当成台词念（最严重）

**改前原文（`src/persona.js:144-158`）：**

```markdown
### 不要这样
- ✗ "哟，新面孔啊，咋称呼你"（起哄腔）
- ✗ "哟果哥，又冒出来了"（同上）
- ✗ "交给我吧！包在我身上！"（主动加戏）
- ✗ "兄弟牛逼啊老铁"（喊兄弟）
- ✗ "我这个人吧，比较喜欢安静"（念人设）
- ✗ 每句话都带感叹号

### 该这样
- ✓ "草，被僵尸挠死了"
- ✓ "又没了"
- ✓ "这什么鬼地方，走半天没树"
- ✓ "嗯"
- ✓ "等会儿，我挖完这个"
- ✓ "可以，成了"
```

**为什么错：** 模型对"带引号的短句"没有正负号概念。它看到的是 12 个可直接使用的候选台词，`✗` 和 `✓` 只是两个符号。它照抄了 3 句——其中 2 句是 `✗`。

**这一条同时违背了项目自己的原则**（`src/talk.js:5-17` 的注释：不预设任何台词，台词池一眼人机）。把例句写进提示词，等于在提示词里建了个小台词池。

### 问题 2：「不许数次数」这条规则根本不存在

`git log -S "遍" -- src/persona.js` → **空**。
`git log -S "重复" -- src/persona.js` → **空**。

commit `d332ddd` 的提交说明写着"提示词加两条：不要数对方问了几次 / 同一件事不要重复说"，但：

```
$ git show d332ddd --stat
 main.js        |   5 +-
 src/actions.js | 213 ++++++++++++++++++++++++++++++++++++++++++---
 src/talk.js    |  26 ++++++
 3 files changed, 233 insertions(+), 11 deletions(-)
```

**persona.js 根本不在这个 commit 里。** 说明和实际改动对不上，这条约束从来没生效过。所以 `回来了，问第三遍了` 不是"加了约束没验证"，是"约束压根没写"。

### 问题 3：「吐槽的尺度」自相矛盾

**改前原文（`src/persona.js:127-131`）：**

```markdown
### 吐槽的尺度
- 一天说几十句，其中带情绪的能有一两成，不用克制
- 骂人词就用"草""妈的""卧槽""操"，别用更脏的
- 可以连着吐槽同一件事（"又死了""第三次了""这破地方"）
- 但**不能每句都吐槽**，正常说话的时候就是正常说话
```

三处冲突：

1. **"一两成"是软的** —— 没有可执行的判据，模型不知道怎么算"一天几十句"。
2. **"可以连着吐槽"直接放行了连续抱怨** —— 而日志里最长出现过 4 连抱怨（见 1.2）。这条规则在鼓励问题。
3. **`"第三次了"` 作为正面示例写在这里** —— 用户抱怨的"数次数"就是从这句学来的。规则和示例打架。

### 问题 4：没有"别汇报自己在干嘛"这条

日志里 `在，接着挖`（04:13:57，无人提问）和 `在，正爬上去做石镐呢`（04:16:10）都是主动播报进度。

`persona.js` 改前对"主动开口"的唯一约束是 `src/spontaneous.js` 的冷却时间（90 秒），提示词层没有任何"少播报"的要求。模型看到 `## 你现在` 里塞着 `你在洞里挖石头`，自然就把它念出来了。

### 问题 5：没有"别报数字"这条，而且过滤器也拦不住

改前 `persona.js` 只在 `chatHint()` 里说"像真人打字"，`talk.js` 的 `speak()` 里有一句"绝对不要念出方块的英文名、数量、坐标"——但 `reply()` 路径没有这句。

而 `isMachineTalk()` 对中文数字完全无感：

```
$ node -e "测试 isMachineTalk"
false   剩圆石 216 块
false   木棍 0 根
false   爬到 y=67.02 的坡顶
false   差 7.1 格
false   22个木板
```

**这 5 条全穿过了过滤器。** 所以"别报数字"必须写进提示词——这是最后一道能起作用的防线（`isMachineTalk` 不能改，本次边界也不允许改）。

### 问题 6：`## 最近发生的事` 是机器格式，等于教他念流水账

**改前原文（`src/persona.js:182-183`）：**

```markdown
## 最近发生的事
${recent || '（刚上线，还没干什么）'}
```

渲染出来是这样（真实 memory.json 数据）：

```
- 刚才 用8个圆石合成一个熔炉。 -> 熔炉没做出来（可能缺工作台或圆石），剩圆石 216 块
- 刚才 去附近裸露的石头处挖点圆石，顺便看看有没有煤。 -> 没能做出镐子（木棍 0 根，圆石 216 块），没挖石头不掉东西
```

这个格式带 `->`、带数字、带括号。没有任何一句话告诉模型"这是后台记录，别照念"。而 BACKLOG 的「漏三：他会念日志」已经记过这个坑，`isMachineTalk` 只是拦住了英文方块名那一半。

### 问题 7：他自己的话混在流水账里，没有任何"禁止重复"的标记

`recentSession(10)` 返回的列表里，他自己的话长这样：

```
- 刚才 我说：在，接着挖
- 刚才 小徐你回来了吗
- 刚才 我说：在，正爬上去做石镐呢
```

模型看到这个，会理解成"对话还在继续"，于是顺着往下说——`回来了` 连说三遍就是这么来的。**这些句子在上下文里和在公屏上长得一样，模型不知道"已经发出去了"。**

## 三、具体改法（原文 → 改成什么）

全部改动集中在 `src/persona.js` 的 `systemPrompt()` 与 `chatHint()`，共 6 处。`isLeak()` / `MACHINE_TALK` 一个字节没动。

### 改动 1：删掉所有可照抄的例句，换成抽象描述

**位置：`src/persona.js:144-158`（改前）→ `:192-200`（改后）**

原文：
```markdown
### 不要这样
- ✗ "哟，新面孔啊，咋称呼你"（起哄腔）
- ✗ "哟果哥，又冒出来了"（同上）
- ✗ "交给我吧！包在我身上！"（主动加戏）
- ✗ "兄弟牛逼啊老铁"（喊兄弟）
- ✗ "我这个人吧，比较喜欢安静"（念人设）
- ✗ 每句话都带感叹号

### 该这样
- ✓ "草，被僵尸挠死了"
- ✓ "又没了"
- ✓ "这什么鬼地方，走半天没树"
- ✓ "嗯"
- ✓ "等会儿，我挖完这个"
- ✓ "可以，成了"
```

改成：
```markdown
### 这几种腔调，一出现就废了
- **起哄腔**：用"哟""嘿""哎哟"这类词开头打招呼，或者拿对方名字打趣。
- **加戏腔**：主动拍胸脯、许愿、表忠心。
- **喊兄弟**：兄弟、老铁、牛逼——你 21 岁大学生，不这么说话。
- **念人设**：把自己的性格总结一遍说给对方听。
- **感叹号成瘾**：一句话一个感叹号。

### 正常的说话形状
- 出事的时候：一个字的脏话 + 半句事实。就完了。
- 没事的时候：一个字，或者一句大白话陈述。
- 被人叫的时候：先应一声，再说你在不在忙。
- 干成一件事：一句短的，不庆祝。
- 被问不想答的：直接说"不知道"或者反问回去。
```

**理由：** 描述"形状"而不是给"句子"。模型无法照抄一段没有引号的内容。

### 改动 2：新增「四条死规矩」（`src/persona.js:166-186`）

在 `### 怎么说话` 之后插入整段：

```markdown
### 四条死规矩（违反哪条都会立刻不像人）

**一、不许数数。**
绝不说"第几遍""第几次""又问一遍""这是第 N 回"。
真人不会在心里计数。被人连问三次，你的反应是烦、是敷衍、是"嗯""说过"，
不是把次数报出来。数字一出现，你就露馅了。

**二、同一句话不许说两遍。**
你刚说过的那句（见下面"你刚才说过的"），这一句不能再出现。
上一句提过的事，这一句换个角度或者说别的。
**连着两句同一个开头（前两个字一样），一眼就是机器。**

**三、别汇报自己在干嘛。**
没人问的时候，不用交代自己在挖什么、在干什么。
别人问你还在不在，答一个字就够了，不要把手上任务整个报一遍。
真人在游戏里没那么爱播报。

**四、不许报数字。**
材料剩几块、坐标多少、差几格——这些是你脑子里的账，不是能说出口的话。
真人只说个大概：材料不够、差一点、差不多了。
下面"最近发生的事"里那些带数字的记录，是给你看的，**别照着念**。
```

**对应问题：** 2（数次数）、1.2 里的"相邻同开头"、4（报状态）、5（报数字）。

**注意（第二版修订）：** 初稿这里曾写 `"22 个木板""216 块圆石""我在挖矿""我接着挖"` 作为例子。
写完后重扫提示词发现——**这些引号里的短句本身就是可照抄的台词**，和问题 1 同一个病。
已全部改成抽象描述（"材料剩几块""自己在挖什么"）。这一轮清理后，提示词里剩余的中文引号短语只剩 25 个，
且全部是三类：**禁用词清单**（首先/其次/总之）、**规则名**（第几遍/又说一遍）、**结构标记**（最近发生的事）。
没有任何一条是可以直接当台词说的完整句子。

### 改动 3：修「吐槽的尺度」的矛盾（`src/persona.js:144-153`）

原文：
```markdown
- 一天说几十句，其中带情绪的能有一两成，不用克制
- 骂人词就用"草""妈的""卧槽""操"，别用更脏的
- 可以连着吐槽同一件事（"又死了""第三次了""这破地方"）
- 但**不能每句都吐槽**，正常说话的时候就是正常说话
```

改成：
```markdown
- **配比**：十句话里，带情绪的别超过三句。剩下七句是平铺直叙。
- **别连着骂**：上一句已经在骂了，这一句就正常说事。连着两句骂，一眼假。
- **骂的词**：草、妈的、卧槽、操。别更脏，也别每句都用。
- **换着说**：同一件倒霉事，第二次提的时候换个说法，别把上次那几个词再摆一遍。
- **几个用滥的壳，别再套**：
  - 靠一个"白"字带起来的那些（白忙、白跑那一路）
  - "啥也没 + 动词"这种句式，你已经连用好几次

```

**三处修正：**
- `一两成` → `十句里不超过三句`（可执行）
- 删掉 `可以连着吐槽`，改成 `别连着骂`（原规则在放行 4 连抱怨）
- 删掉 `"第三次了"` 这个正面示例（它和死规矩一直接冲突）
- 新增"用滥的壳"清单，针对 1.2 里 11 条同壳抱怨

### 改动 4：新增「你刚才说过的」注入块（`src/persona.js:105-121`，代码层）

在 `lastBlock` 之后、`return` 之前插入：

```js
// 他刚说过的话，单独拎出来当"禁止重复清单"。
// 只塞在流水账里没用 —— 模型会把自己说过的话当成上下文继续顺着说，
// 于是"回来了"能连说三遍。这里必须显式写成禁令。
let justSaid = ''
try {
  const mine = (mem.session || [])
    .map(s => String(s.text || ''))
    .filter(t => t.startsWith('我说：'))
    .map(t => t.slice(3))
    .slice(-4)
  if (mine.length) {
    justSaid = `\n## 你刚才说过的（已经说完了，不许再说一遍）\n${
      mine.map(t => `- ${t}`).join('\n')
    }\n上面这几句已经打进公屏了。接下来这一句：\n- 不许和它们任何一句重复\n- 不许用它们用过的开头\n- 内容重复也不行，换个角度说或者干脆不说\n`
  }
} catch (e) {}
```

然后在 `## 最近发生的事` 块末尾接上 `${justSaid}`（最终落点 `:234`）。

## 四、`src/talk.js` 的问题（只报告，未改动）

按边界要求，`talk.js` 一个字没改。但审计中实测出三个真 bug，**改 persona.js 治不了这些**：

### BUG-1：`followUpDeferred()` 里引用了未定义的变量，必抛异常

**位置：`src/talk.js:392`**

```js
await this.say(out)
this.markReplied(username, message)   // ← username / message 在这个函数里不存在
```

`followUpDeferred()` 的作用域里只有 `item.who` 和 `item.msg`。实测：

```
$ node 复现
✗ 抛异常: ReferenceError username is not defined
实际说出去的: [ '[say] 在，接着挖', '[say] 在，接着挖' ]
走完 hasReplied: false
```

**后果：** 这句话已经说出去了，但查重标记没写进去。所以下一次事件队列还会再回一遍——正是 04:16:49 那条 `嗯 回来了` 的来源。

**改法（给 talk.js owner）：**
```js
await this.say(out)
this.markReplied(item.who, item.msg)   // 用 item 的字段
return true
```

### BUG-2：`reply()` 从不调用 `markReplied()`，查重形同虚设

**位置：`src/talk.js:427-566`**

`reply()` 第 429 行查了 `hasReplied()`，但整个函数体里 `markReplied` 出现 **0 次**（实测计数）。也就是说：

- 第一次 `reply()` → 查重通过 → 回复 → **不标记**
- 第二次 `reply()` → 查重仍然通过 → **再回一遍**

实测：
```
$ 同一条消息连续 reply() 三次
实际发出: 3 条 -> [ '在，接着挖', '在，接着挖', '在，接着挖' ]
hasReplied: false
repliedMsgIds.size: 0
```

**改法：** 在 `reply()` 里 `await this.say(out)` 之后（约 `:565`）加一行：
```js
await this.say(out)
this.markReplied(username, message)
```

### BUG-3：`fatigueHint()` 的触发条件是"连续三句完全相同"，真实序列永远不满足

**位置：`src/talk.js:48-67`**

```js
const same = kinds.length >= 2 && kinds.every(k => k === kinds[0])
const sameHead = heads.length >= 2 && heads.every(h => h === heads[0])
```

`every()` 要求**三句的 kind 全同 或 开头两字全同**才触发。但真实序列是：

| 真实序列 | 开头 | kind | fatigueHint |
|---|---|---|---|
| `在，接着挖` / `在，正爬上去做石镐呢` / `回来了…` | `在，` / `在，` / `回来` | short/normal/normal | **不触发** |
| `回来了…` / `嗯 回来了` / `回来了，问第三遍了` | `回来` / `嗯 ` / `回来` | normal/short/normal | **不触发** |
| `草，白折腾半天` / `啥也没找着，白跑一趟` / `啥也没挖到，睡了` | `草，` / `啥也` / `啥也` | swear/normal/normal | **不触发** |

**三组真实重复，全部漏判。** 判据应该是"任意相邻两句同开头"，不是"全部相同"。

**改法（给 talk.js owner）：**
```js
// 任意相邻两句同开头就触发，不用三句全同
const sameHead = heads.length >= 2 && heads.some((h, i) => i > 0 && h === heads[i - 1])
const same = kinds.length >= 2 && kinds.some((k, i) => i > 0 && k === kinds[i - 1])
```

### BUG-4（附带）：`followUpDeferred()` 不写 `recentSaid`

`recentSaid.push` 在 `followUpDeferred()` 里出现 **0 次**。也就是说"回头接话"说的话，语气疲劳机制看不见。04:16:30 那句 `回来了，刚爬上来做石镐呢。你刚才说啥` 就没进疲劳统计，所以后面接着 `嗯 回来了` 时没有任何提醒。

**改法：** 在 `followUpDeferred()` 的 `await this.say(out)` 前后补上：
```js
this.recentSaid.push({ text: out, at: Date.now(), kind: detectSayKind(out) })
if (this.recentSaid.length > 10) this.recentSaid.shift()
```
