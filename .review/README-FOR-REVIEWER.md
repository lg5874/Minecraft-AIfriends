# 给代码审查者：项目背景

你要审的是一个 **Minecraft AI 玩家**项目。不是 NPC，不是聊天机器人，
是一个"真的在玩"的玩家，跟 3-4 个真人一起在服务器上玩。

## 最重要的三条约束（违反就废了）

1. **他必须坚信自己是人，永远不知道自己是程序。**
   所以代码里有 `persona.isLeak()` 过滤，命中就整句作废。
   不要建议"让他更诚实"或"加入 AI 身份声明"。

2. **不要预设台词。**
   我们试过随机抽台词池（"搞定了""我又来了""草，掉岩浆了"），
   结果他一遍遍说同样的话，一眼人机。
   现在的做法是每个情境让模型现编。**不要建议加台词池。**

3. **他会忘事，这是设计不是 bug。**
   记忆有衰减机制：普通事件 6 小时半衰期，恩怨 40 小时，承诺和技能不忘。
   刻骨铭心的（情感≥0.7 或重要性≥0.8）永不衰减。
   **不要建议"全部永久记住"。**

## 现在最大的问题

**任务失败率 78%。**

从他 65 条记忆统计：成功 4，失败 14，说不清 23。

典型失败：
- "向下挖了 0 格深的避难坑"
- "一个箱子也没放成"
- "熔炉没合出来"
- "只挖到 0 块圆石"

## 我（开发 AI）已经查到的根因

### 【A】容器打开超时 20 秒（最严重）
```
Error: Event windowOpen did not fire within timeout of 20000ms
```
实测正常打开只要 317ms，所以这是偶发。但一旦发生，白等 20 秒后任务判失败。
mineflayer 的 `openBlock` / `openFurnace` / `openContainer` 默认等 20 秒。

### 【B】工作台"丢了"就放弃
`craftSmart()` 里 `findBlock('crafting_table', 24)` 找不到就报错。
但工作台可能在背包里（没放下去），或者被自己挖走了。

### 【C】"挖到 0 块"——数太早
`mine()` 挖完后立刻 `countOf()`，但物品还没进背包（需要走过去捡）。
`pickupNearby()` 只是走过去，没等物品真的进背包。

### 【D】箱子放不下
`findPlaceSpot()` 要求"脚下有实体 + 当前格空 + 头顶空"三个同时满足，太严。

### 【E】失败不知道错在哪
78% 的失败，日志只有"没做成"，没有具体卡在哪一步。

## 请你做的事

**只审查，不要改代码。** 输出一份报告，回答：

1. 上面 A-E 五个根因，我的判断对不对？有没有判断错的？
2. **有没有我漏掉的根因？** 这是最有价值的。
3. 哪些地方的设计本身有问题（不是 bug，是架构问题）？
4. 如果要修，你会怎么修？给出具体方案（伪代码即可）。
